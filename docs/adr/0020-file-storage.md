# ADR-020: File storage through the S3 API with a local-disk fallback

- Status: Accepted
- Date: 2026-10-12
- Backlog: M0-024

## Context

Attachments (CORE-021) need previews, ZIP browsing, admin-set size limits with no fixed ceiling,
no storage quota, and serving through short-lived signed URLs under the browse permission. Small
installs want zero extra services (ADR-006); larger ones already have object storage.

## Decision

- **One storage interface** in `packages/storage`: `put` (streaming, content-addressed by
  SHA-256), `get` as a stream or a signed URL, `delete`, `stat`, with per-workspace prefixes.
- **Local disk is the default** (`/data/files`), with files written under their hash and
  served by the backend through signed, expiring URLs; the same interface makes the Compose
  kit's volume the only thing to back up.
- **S3-compatible is the second implementation** through `@aws-sdk/client-s3`: AWS S3, MinIO,
  Garage, SeaweedFS, Cloudflare R2 and others; presigned URLs for download and, for large
  files, multipart upload direct from the browser. Server-side encryption settings pass through.
- **Metadata lives in Postgres** (name, size, type, hash, uploader, item); deduplication is by
  hash per workspace; deletion follows the trash retention (CORE-025) and then removes the
  object. Virus scanning is an optional hook (ClamAV) in M2.
- **Migration between backends** is a CLI command that copies objects and flips the setting.

## Options considered

| Option | For | Against |
|---|---|---|
| Interface with local disk and S3 (chosen) | Zero services for small sites; standard API for large ones; Plane's experience shows swapping S3-compatible stores is routine | Two implementations to test (one shared contract suite) |
| Require MinIO | One code path | A fourth container for a 10-user install; MinIO's licence (AGPL) is fine but its project direction is uncertain |
| Store bytes in Postgres | Transactional | Bloat, backup size, no streaming; wrong for multi-gigabyte files |

## Consequences

Backups (ADR-022, OPS-008) handle the two backends differently (file copy versus bucket
replication), documented in the kit README. Previews and thumbnails are generated by the worker
and stored through the same interface.
